# devflow-lab

## Цель и текущий объём
Учебный репозиторий седьмой недели курса — AI в рабочем процессе разработчика: ассистент проекта, ревью PR,
пайплайны, субагенты. Каркас скопирован из rag-lab (ядро, LLM, CLI, реестры, tooling, фича rag) и mcp-lab
(MCP-клиент) без общих пакетов (ADR 0001).
Реализованы: RAG по документации проекта — корпус из `rag.include` внутри `project.root` (по умолчанию сам репозиторий),
чанкинг по структуре Markdown, эмбеддинги Ollama, ответ с источниками, цитатами и «не знаю» (`rag index`, `rag ask`);
`ask` с циклом инструментов MCP-серверов, открываемых на реплику. MCP-серверов пока нет, `servers/` пуст.
Задания выдаются по одному; docs/course.md — ориентир недели, он не разрешает реализовывать будущие задания заранее.
Перед заданием сформулируй учебную цель и минимальный результат; улучшения отдели явно.

## Зависимости
app связывает core, адаптеры и публичные входы фич.
core не импортирует SDK, Node API, адаптеры, app или фичи.
Фича не импортирует другую фичу; снаружи доступен только её index.ts, тесты app не берут файлы из tests фичи.
Адаптер может реализовать публичный порт фичи; обратный импорт запрещён.
Специфический адаптер хранится внутри фичи (Ollama — в features/rag), общий — в adapters.
Серверы не импортируют host или соседние серверы; host не импортирует серверы, а запускает их процессом.
Один composition root на процесс. Регистрация явная, динамического поиска плагинов нет.
Точки расширения — ModelPort, ToolSource и EmbeddingPort фичи rag. Новые контракты (пайплайн, субагенты,
ToolExecutor, хранилища) — только через ADR с конкретным потребителем.
Новая фича использует контракт; не добавляй ветвление по её имени в core.

## Глоссарий
- Проект (`project.root`): репозиторий, о котором отвечает ассистент; по умолчанию сам devflow-lab.
- Корпус: Markdown-файлы проекта по шаблонам `rag.include`; frontmatter необязателен.
- Чанк: фрагмент документа по заголовкам и целым блокам; диапазон `start`–`end` в кодовых точках Unicode.
- Индекс: `index.json` (`formatVersion: 2`) с документами, чанками, эмбеддингами и параметрами построения.
- Эмбеддинг: вектор чанка от модели Ollama; EmbeddingPort — порт фичи rag, не ModelPort.
- Режим поиска (`rag.retrievalMode`): `baseline`, `filter`, `rewrite`, `rewrite-filter`; по умолчанию `rewrite-filter`.
- Кандидаты: результат поиска до отбора (`rag.candidateTopK`); порог — `rag.similarityThreshold`, top-K — `rag.topK`.
- Цитата: строка `- [N] «текст»`; засчитывается, если после нормализации это подстрока текста чанка `[N]`.
- «Не знаю»: ответ без источников; при пустом отборе формирует код без вызова модели.
- MCP-сессия: процесс сервера и клиент на одну реплику `ask`; ToolSource — её вид для Agent.
- Лимит вызовов (`ASK_MAX_TOOL_CALLS`): сколько вызовов инструментов Agent исполнит за реплику.
- Провайдер модели (`llm.provider`): `deepseek` или `local`; эмбеддинги от него не зависят.
- Agent: обрабатывает реплику через ModelPort, состояния не хранит. Command — команда CLI/REPL; tool — действие модели.

## Конфигурация и команды
Реестр настроек: apps/host/src/app/settings.ts; описания: settings.md рядом.
Приоритет: defaults < YAML-файл < env < CLI. config show показывает источник.
Env и флаги выводятся из ключа. Секреты — только env, без значений в выводе и файлах.
process.env и process.argv читаются только в app/main.ts; дальше передаются явно.
Реестр команд: apps/host/src/app/commands.ts; один dispatch для CLI и REPL.
Справка и docs/configuration.md, docs/commands.md генерируются из реестров.
Лимиты — зарегистрированные настройки или именованные константы, не числа внутри циклов.

## Markdown и структура
Инструкции модели, заметки, отчёты — Markdown; метаданные — YAML frontmatter.
Структура допустима для API/MCP, схем инструментов, YAML-настроек и машинного состояния (`index.json`).
Не собирай смысловой контекст через JSON.stringify. System prompt — app/system.md; инструкции rag — features/rag/prompts/.
Запись файла: временный рядом + rename. Не добавляй хранилища и миграции без задания.
Индекс лежит в `.local/` (вне git); воспроизводимые измерения и выводы — в docs/demos или experiments/ по заданию.

## Песочница инструментов
MCP-инструменты по умолчанию только читают: файлы проекта, git status/diff/log/branch, поиск, анализ структуры.
Запись, сеть, произвольные команды и разрушающие операции (удаление, push, смена конфигов) — только через отдельный
ADR и явное подтверждение человека перед вызовом. Аргументы инструмента не выводят за `project.root`.
Сервер получает только объявленные `env`; ключи модели и остальное окружение host ему не передаются.

## Guardrails и красные флаги
Перед фичей укажи контракт, папку, настройки, команды и тестируемый результат.
Нет подходящего контракта — остановись и предложи ADR, согласуй изменение ядра.
Обычная область PR: своя фича или сервер, composition root, документация; чужой код — с обоснованием.
Остановись и согласуй решение при if по фиче в ядре, расширении общего порта ради одной фичи,
импорте соседней фичи, обходе реестров, ручной справке, UI-тексте в ядре или промпте в TS/JSON.
`help` с аргументами для ассистента не должен ломать `help`/`--help` без аргументов (ADR 0002).
dependency-cruiser проверяет границы, циклы и import type, включая workspace-импорты.
Пределы: 300 строк кода в файле, 400 в тесте, 60 в функции, 120 физических строк в AGENTS.md.
Исключение размера функции — только контейнер describe; it, hooks и helpers проверяются.
Фича содержит README.md, index.ts и tests/*.test.ts. prompts/ — только по необходимости.
Обход проверки или исключение требуют отдельного ADR; существующего allowlist нет.
Тесты без внешних API: fake ModelPort и EmbeddingPort, подменённые fetch и MCP-сессии, временные каталоги.
Документация на русском. Комментарий — 1–2 строки о неочевидном факте; старые не переписывай без просьбы.
Устаревшие факты исправляй на месте. Причины ошибок и названия тестов должны быть точными.

## Definition of Done
- Минимальная цель задания выполнена; будущие направления не реализованы попутно.
- Содержательные тесты и npm run check проходят; границы не ослаблены.
- Документация и генерируемая справка актуальны; секреты не попали в файлы и вывод.
- Для наблюдаемого поведения есть короткое воспроизводимое демо в docs/demos.
- Измерения (время, стоимость, доля успешных прогонов) отделены от оценок; ограничения названы явно.
