# Правила host

Общие правила находятся в [корневом AGENTS.md](../../AGENTS.md).

- main.ts читает окружение и argv, compose.ts связывает зависимости.
- Agent хранит только модель, системную инструкцию и лимит вызовов инструментов; между вызовами respond() состояния нет,
  историю передаёт вызывающий: `respond(input, { tools, history })`.
- Agent проверяет весь ответ модели с tool_calls до исполнения и исполняет вызовы по порядку, не больше `maxToolCalls`.
- Публичный порт ядра — ModelPort.complete(request: ModelRequest): Promise<ModelCompletion>; не добавляй методы ради будущих фич.
- Провайдер-специфичные параметры и SDK-типы не выходят из adapters/llm. SDK-повторы отключены.
- Порт эмбеддингов — EmbeddingPort фичи rag; ModelPort для эмбеддингов не расширяется.
- `ask` и `info <вопрос>` открывают MCP-сессии серверов из `RunOptions.mcpServers` на каждую реплику (app/ask.ts,
  app/info.ts, app/toolSources.ts); по умолчанию это git-сервер с корнем `project.root`, тесты передают свой список.
  Модель (и для `info` — индекс) создаётся до запуска серверов: ошибка ключа или индекса приходит раньше.
- `help` — только справка по командам и настройкам, без модели; вопросы о проекте — команда `info` (ADR 0002).
- `review <база>` (app/review.ts, ADR 0003) создаёт модель и индекс, затем открывает ту же MCP-сессию, но git-инструменты
  вызывает сам и разбирает текст `git_changed_files` по контракту README сервера; модель вызывается один раз без
  инструментов. Ошибка git-инструмента показывается текстом сервера: его готовит `describeGitError`, без stderr git.
- `support <тикет> <вопрос...>` (app/support.ts, ADR 0004) открывает только сервер поддержки (`supportServer`, не из
  `RunOptions.mcpServers`), сам вызывает `get_ticket` и передаёт текст модели не разбирая; модель — один раз без
  инструментов, инструкция — `features/support/prompts/support.md` без `app/system.md`.
- `files <цель...>` (app/files.ts, ADR 0005) — две фазы: `plan` (модель с `files_search`, `files_read`, git-инструментами
  без `read_file` и локальным `propose_edit`; `files_write` скрыт `withoutTools`) и `apply` (новая сессия files-сервера
  после `[y/N]`; подтверждение только при TTY, ответ читает readline REPL). Правки копятся в памяти, файлы меняет
  только `apply`.
- CLI отображает AgentError, RagError и McpToolSourceError; не печатает необработанные ошибки SDK, тела ответов Ollama,
  аргументы и результаты инструментов, значения настроек.
- Команда описывается в app/commands.ts один раз; CLI и REPL используют один dispatcher.
- Настройки описываются в app/settings.ts; тексты справки и описания находятся рядом в .md.
- Поиск, rewrite, отбор и склейка фрагментов — в features/rag; app передаёт настройки и связывает зависимости.
- Индекс пишется только целиком: собирается в памяти, затем временный файл рядом и rename.
- Тесты лежат рядом с модулем в tests; тесты app используют harness.ts, а не файлы tests фичи.
- npm run check выполняется из корня монорепозитория.
