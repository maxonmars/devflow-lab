# Описания команд

## ask
Отправить реплику агенту без поиска по документам и без истории. Агент может вызывать инструменты подключённых MCP-серверов; до появления первого сервера ответ идёт без инструментов. Нужен LAB_LLM_API_KEY при llm.provider: deepseek.

## info
Ответ ассистента проекта: фрагменты документации project.root из index.json и git-инструменты проекта (ветка, статус, diff, изменённые и отслеживаемые файлы, содержимое файла в HEAD), которые модель вызывает сама. Ответ содержит источники с проверенными цитатами и раздел «Данные проекта» с фактами инструментов. Нужны индекс, запущенная Ollama и LAB_LLM_API_KEY при llm.provider: deepseek.

## support
Ответ клиенту по тикету (например, `support T-1001 Почему не работает авторизация?`): host берёт тикет и клиента из JSON support.dataFile через MCP-сервер поддержки, RAG находит фрагменты документации продукта по вопросу и тексту тикета, модель один раз отвечает разделами «Ответ», «Источники» и «Данные тикета». Неизвестный тикет — ошибка без вызова модели. Нужны индекс, запущенная Ollama и LAB_LLM_API_KEY при llm.provider: deepseek.

## help
Показать команды и флаги настроек.

## config show
Показать действующие настройки и их источники без значений секретов.

## rag index
Собрать корпус из Markdown-файлов rag.include внутри project.root, разбить его на чанки по заголовкам и блокам Markdown, получить эмбеддинги через Ollama и сохранить индекс в index.json. Нужны запущенная Ollama и скачанная модель.

## rag ask
Найти в index.json фрагменты по вопросу в режиме rag.retrievalMode (по умолчанию rewrite-filter) и ответить по ним, без истории: каждый вопрос одиночный. Ответ содержит источники и цитаты; если после отбора фрагментов нет — «не знаю» с просьбой уточнить вопрос без вызова модели. Нужны индекс, запущенная Ollama с моделью индекса и LAB_LLM_API_KEY при llm.provider: deepseek.

## review
AI-ревью изменений текущей ветки относительно базы (`base...HEAD`, например `review main` или `review origin/main`): git-сервер даёт список изменённых файлов, diff и содержимое каждого файла в HEAD, RAG находит фрагменты документации по diff, модель один раз пишет разделы «Потенциальные баги», «Архитектурные проблемы» и «Рекомендации». Без изменений модель не вызывается. С review.outputFile тот же Markdown пишется в файл. Нужны индекс, запущенная Ollama и LAB_LLM_API_KEY при llm.provider: deepseek.

## exit
Завершить ввод реплик.
