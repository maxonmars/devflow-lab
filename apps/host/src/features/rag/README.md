# Фича rag: индексация, поиск, отбор по порогу, ответ с источниками и цитатами, чат с памятью задачи

Читает Markdown-корпус, режет его двумя стратегиями, получает эмбеддинги через Ollama и сохраняет `index.json`.
Отчёт сравнения стратегий читает индекс. Поиск находит кандидатов по вопросу, второй этап отбирает их по порогу
сходства, `answerWithRag` склеивает итоговые чанки с исходным вопросом в Markdown и отправляет модели. Запрос для
поиска можно переписать моделью. Ответ модели разбирается в `CitedAnswer`: текст, источники и цитаты, проверенные на
дословность; при пустом отборе модель не вызывается, ответ — «не знаю». `calibrateThreshold` подбирает порог,
`evaluateQuestions` сравнивает четыре режима, `evaluateCitations` прогоняет вопросы в одном режиме и проверяет цитаты.
Решения — [ADR 0002](../../../../../docs/adr/0002-document-indexing.md) (индексация),
[ADR 0003](../../../../../docs/adr/0003-first-rag-query.md) (RAG-запрос),
[ADR 0004](../../../../../docs/adr/0004-relevance-filter-and-query-rewrite.md) (порог, rewrite, калибровка, сравнение) и
[ADR 0005](../../../../../docs/adr/0005-citations-and-refusal.md) (источники, цитаты, «не знаю») и
[ADR 0006](../../../../../docs/adr/0006-rag-chat-memory.md) (чат: история и память задачи).

## Публичный контракт (`index.ts`)

- `indexCorpus(options)` — корпус → чанки `fixed` и `structure` → эмбеддинги → `index.json`. Индекс заменяется целиком
  после успеха всех запросов; при ошибке прежний файл остаётся. Возвращает счётчики, токены и время по стратегиям.
- `compareIndex({ indexFile, reportFile })` — читает индекс и пишет `comparison.md` без обращения к модели.
- `openIndex({ indexFile, embeddings })` — читает индекс один раз и проверяет digest модели эмбеддингов; возвращает
  `SearchIndex` с `search(question, strategy, topK)`: эмбеддинг вопроса → косинусная близость по чанкам одной
  стратегии → `SearchHit[]` (`rank` с 1, `score`, чанк без вектора).
- `answerWithRag({ question, index, strategy, mode, candidateTopK, topK, threshold, model, systemPrompt, answerPrompt })` — rewrite
  (по режиму) → поиск `candidateTopK` кандидатов → отбор → ответ `Agent`; системная инструкция вызывающего дополняется
  шаблоном ответа `answerPrompt` (`prompts/answer.md` или `answer-compact.md`). Пустой вопрос — `AgentError EMPTY_INPUT`, несогласованные параметры — `INVALID_RETRIEVAL_PARAMS`,
  оба до rewrite и поиска. Возвращает `answer` (`CitedAnswer`), итоговые `hits`, `contextChars`, фактическую строку поиска
  `query`, исходные `candidates` и длительности этапов `timings` (`rewriteMs`, `searchMs`, `selectMs`, `generateMs`).
- `renderCitedAnswer(answer)`, `describeCitationProblem(problem)` — единственный текст ответа для CLI и отчётов и русские
  описания замечаний к контракту.
- `ANSWER_PROMPTS` (`default`, `compact`), `AnswerPrompt` — шаблоны инструкции ответа (ADR 0008); `answerPrompt` обязателен в опциях
  `answerWithRag`, `evaluateQuestions`, `evaluateCitations`, `chatTurn`, `evaluateDialogs`, шапки отчётов называют шаблон.
- `RETRIEVAL_MODES` (`baseline`, `filter`, `rewrite`, `rewrite-filter`), `RetrievalMode`, `checkRetrievalParams(params)`,
  `MAX_TOP_K`, `SIMILARITY_RANGE`, `usesFilter(mode)` — единый набор режимов и единственная проверка параметров.
- `calibrateThreshold(options)` — один поиск исходной формулировкой на вопрос, сетка порогов, `rag-calibration.md`;
  модель генерации не нужна.
- `evaluateQuestions(options)` — читает контрольные вопросы, для каждого запускает все четыре режима на общих кандидатах,
  считает метрики и пишет `rag-eval.md`; первая ошибка прерывает прогон, отчёт не пишется.
- `evaluateCitations(options)` — читает контрольные вопросы, для каждого вызывает `answerWithRag` в одном режиме, считает
  метрики источников, цитат и отказов и пишет `rag-citations.md`; ошибка модели (`AgentError`) становится исходом вопроса,
  прочие ошибки прерывают прогон, отчёт не пишется.
- `chatTurn({ dialog, question, index, strategy, mode, model, systemPrompt, historyTurns, candidateTopK, topK, threshold })` —
  один ход чата без состояния: память задачи → rewrite (по режиму) → поиск → отбор → ответ с историей. Возвращает `turn`
  (`DialogTurn`) и новый `dialog`; входной диалог не меняется, ошибка шага отклоняет промис. Пустой вопрос, несогласованные
  параметры и `historyTurns` вне 1–20 отклоняются до любых вызовов.
- `Dialog`, `DialogTurn`, `EMPTY_DIALOG`, `MAX_HISTORY_TURNS`, `TaskState`, `renderTaskState` — модель данных диалога и память
  задачи; разбор ответа памяти наружу не экспортируется.
- `evaluateDialogs(options)` — читает сценарии, каждый прогоняет в новом диалоге, считает метрики и пишет `rag-dialog.md`;
  первая ошибка прерывает прогон, отчёт не пишется.
- `EmbeddingPort` — `embed(texts)` (векторы, `prompt_eval_count` и `load_duration` пакета) и `describeModel()`.
- `createOllamaEmbeddings(options)` — адаптер Ollama `/api/embed` и `/api/tags` с внедряемым `fetch`.
- `RagError`, `describeRagError` — типизированные ошибки и русские сообщения для CLI.

## Режимы поиска и отбор

| Режим | Строка поиска | Порог |
|---|---|---|
| `baseline` | исходный вопрос | нет |
| `filter` | исходный вопрос | да |
| `rewrite` | переписанный запрос | нет |
| `rewrite-filter` | переписанный запрос | да |

Поиск (`SearchIndex.search`) остаётся низкоуровневым: он возвращает `candidateTopK` кандидатов по убыванию сходства.
Отбор — отдельная чистая функция над готовым списком: при фильтре оставляет `score >= порог`, затем берёт первые
`topK`; порядок и score не меняются, дубликаты файлов не убираются, чанки ниже порога не добираются. Отдельно считаются
кандидаты, удалённые порогом, отброшенные конечным K и переданные модели. Фильтр не реранжирует: он удаляет слабый хвост.
Кандидаты отсортированы, поэтому итог — префикс списка, и `candidateTopK` > `topK` сам по себе не меняет выдачу
threshold-фильтра. Параметры проверяются до внешних вызовов: оба K — целые от 1 до 20, `topK` ≤ `candidateTopK`, порог
— число от −1 до 1.

**Переписывание запроса.** Один вызов `Agent` с инструкцией `prompts/rewrite.md`, без истории и инструментов; в генерацию
всегда идёт исходный вопрос. Ответ должен быть одной строкой: несколько строк или Markdown-забор — `REWRITE_INVALID`,
пустой ответ — `AgentError EMPTY_RESPONSE`. Запрос не извлекается из произвольного ответа, вызов не повторяется, исходный
вопрос скрыто не подставляется.

**Пустой контекст.** Если отбор ничего не оставил, модель не вызывается: ответ — «не знаю» с просьбой уточнить вопрос,
`contextChars` равен 0. В режимах с фильтром текст называет порог и ближайшие разделы ниже него, в `baseline` и `rewrite` —
что поиск ничего не вернул. CLI показывает «Фрагменты: контекст пуст» — это не утверждение об отсутствии ответа в корпусе.

**Калибровка.** `rag calibrate` проверяет пороги 0.50, 0.55, 0.60, 0.65 на общих кандидатах. Baseline — первые `topK`
кандидатов без порога. Выбор — лексикографический максимум: сохранённые уникальные пары «вопрос — ожидаемый файл», затем
число отрицательных вопросов с пустым итоговым контекстом, затем порог. Потеря источника не компенсируется отсечением
отрицательного вопроса; считается по точным score.

**Сравнение режимов.** На вопрос — исходный поиск (baseline, filter), один rewrite и один поиск переписанной строки
(rewrite, rewrite-filter): два поиска, один rewrite, до четырёх генераций (в режимах с фильтром при пустом контексте
генерации нет). Метрики по итоговым hits: hit@K, MRR и покрытие
источников — по положительным вопросам, доля непустого контекста — по отрицательным; пустой знаменатель — «—». Время
режима — сумма его этапов (общие этапы входят в оба режима пары), фактическая длительность прогона — отдельно.

## Формат `index.json` (`formatVersion: 1`)

| Поле | Содержимое |
|---|---|
| `createdAt`, `corpusHash` | время построения; sha256 от списка файлов и хешей их текста |
| `params` | `chunkSizeChars`, `overlapChars`, `minChunkChars` |
| `model`, `modelLoadMs` | `name`, `digest`, `dimension`; `load_duration` прогрева |
| `documents[]` | `file`, `source`, `title`, `hash`, `text` (нормализованный), `blocks[]` (`type`, `start`, `end`, `section`) |
| `strategies.fixed`, `strategies.structure` | `chunkingMs`, `embeddingMs`, `promptTokens`, `chunks[]` |
| `chunks[]` | `chunk_id`, `strategy`, `source`, `title`, `file`, `sections[]`, `start`, `end`, `text`, `embedding` |

Диапазоны `start`–`end` — кодовые точки Unicode: `text` равен срезу `documents[].text` по диапазону.

## Сообщение в режиме RAG

Пользовательское сообщение собирает `renderRagMessage` как Markdown; инструкции модели в нём нет, они в `prompts/answer.md` (или `answer-compact.md`):

````text
## Фрагменты документации

### Фрагмент 1

- Файл: `structure/global.md`
- Документ: Global
- Разделы: Global › Правило; Global › Почему

```markdown
<текст чанка как есть>
```

## Вопрос

<вопрос>
````

Забор длиннее любой серии обратных кавычек в тексте чанка. Сходство и URL источника модели не передаются. Без фрагментов
сообщение не собирается: модель не вызывается.

## Формат ответа и проверка цитат

Инструкции `prompts/answer.md` и `answer-compact.md` требуют Markdown-разделы: `## Ответ`, `## Источники`, `## Цитаты` либо, если во
фрагментах нет сведений, `## Не знаю` и `## Уточнение`. Источник — строка `- [N]`, цитата — `- [N] «текст»`, где `N` — номер
из заголовка «Фрагмент N», то есть `rank` чанка. `parseCitedAnswer` разбирает ответ и возвращает `CitedAnswer`:

| Вид | Поля |
|---|---|
| `answer` | `text`, `sources` (`fragment`, `hit`), `quotes` (`fragment`, `text`, `hit`, `verified`), `problems`, `raw` |
| `unknown`, `by: "model"` | `text`, `clarification`, `problems`, `raw` — модель сама отказала при непустом контексте |
| `unknown`, `by: "retrieval"` | `threshold` (`null` без фильтра), `nearest` — до трёх кандидатов ниже порога; модель не вызывалась |

Код раскрывает `[N]` в `file`, `sections`, `chunk_id` и `source` чанка. Цитата засчитывается, если после нормализации
(NFC, регистр, «ё» → «е», удаление `` ` ``, `*`, `_`, тире → `-`, кавычки → `"`, пробелы) она — подстрока текста указанного чанка;
короче `MIN_QUOTE_CHARS` (20) — замечание. Нарушения контракта (`format`, `unexpected-section`, `no-sources`, `no-quotes`,
`no-clarification`, `unknown-fragment`, `source-without-quote`, `quote-not-found`, `quote-too-short`) возвращаются в `problems`, а не
бросаются; модель повторно не вызывается. `renderCitedAnswer` показывает ответ, источники и цитаты с отметкой «найдена»
или «не найдена» и блок «Замечания».

## Контрольные вопросы

Файл `experiments/feod-retrieval/questions.md`: раздел `## qNN. Вопрос`, строки `Ожидание:` и `Источники:` (файлы корпуса
через запятую, `—` — ответа в корпусе нет; такой вопрос отрицательный). Ошибки формата — `QUESTIONS_INVALID` с причиной;
источник, которого нет в индексе, отклоняется до первого поиска и вызова модели. Отчёт `rag-eval.md` содержит сводку
режимов, исходный и переписанный запрос, кандидатов со scores и причиной исключения, ответы всех режимов и время этапов;
оценки качества в него не входят. Отчёт `rag-citations.md` — сводка по источникам, цитатам, отказам и ошибкам модели, раздел «Время этапов» (медиана и максимум
rewrite, поиска, генерации и всех этапов), таблица вопросов со временем rewrite и генерации, переданные фрагменты с `chunk_id`
и ответы; вопрос с ошибкой модели описан причиной вместо ответа. Смысл ответов в отчёте не оценивается.

## Чат и память задачи

Код лежит в `chat/` (подкаталог фичи): `taskState.ts` — тип, рендер и разбор памяти, `dialog.ts` — `Dialog`, `DialogTurn` и
сообщения истории, `turn.ts` — `chatTurn`, `scenarios.ts`, `dialogMetrics.ts`, `dialogReport*.ts`, `dialogEval.ts` — сценарии и
`rag dialog`. Диалог хранит вызывающий (`app/compose.ts`), фича состояния не держит.

**Память задачи.** `TaskState = { goal, clarifications, constraints }` — Markdown-разделы `## Цель`, `## Уточнения`,
`## Ограничения и термины`; пустое значение — «—». Обновляет её один вызов `Agent` с `prompts/task-state.md` до rewrite и поиска; на входе текущая память и новое сообщение
пользователя, ответов ассистента нет.
Ответ без непустой «Цели» не разобран: память остаётся прежней, `DialogTurn.stateUpdated` равен `false`. Пункт «- —» считается
пустым разделом.

**История.** Модели уходят последние `rag.historyTurns` ходов отдельными `user`/`assistant`-сообщениями. Ответ ассистента в истории —
в формате ответа модели: `## Ответ` с `[N]`, `## Источники` строками `- [N] \`файл\` › раздел`, `## Цитаты`; отказ — `## Не знаю` и
`## Уточнение`, при отказе по отбору — фиксированная фраза. Номера относятся к фрагментам своего хода, поэтому источник дополнен
файлом. Rewrite получает память и две последние реплики текстом и берёт из памяти только то, на что ссылается вопрос.

**Сообщение ответа.** Системная инструкция вызывающего + шаблон ответа (`answer.md` или `answer-compact.md`) + `chat.md`; сообщение пользователя —
`## Память задачи` (разделы памяти понижены до `###`), `## Фрагменты документации`, `## Вопрос`. Память и история не источник
фактов: источники и цитаты берутся из фрагментов текущего сообщения, формат ответа и проверка цитат прежние (ADR 0005).

**Сценарии.** `experiments/feod-chat/scenarios.md`: `## sN. Название`, поля `Цель:`, `Ключи цели:` (через запятую), необязательная
`Память:` (строки `- N: ключ`, N — номер реплики, где пользователь задал ключ) и нумерованные `Реплики:`. Ошибки —
`SCENARIOS_NOT_FOUND` и `SCENARIOS_INVALID` с причиной (`empty`, `heading`, `goal`, `goalKeys`, `messages`, `memory`, `duplicate`).
Метрики сценария: ходы, ответы, ответы с источником и с дословной цитатой, цитаты, «не знаю» (по пустому отбору и моделью),
ходы с сохранённой целью (каждый ключ цели — подстрока цели из памяти), удержанные ключи памяти (подстрока памяти, с хода N),
ходы с неразобранной памятью и ответы с замечаниями. Это подстроки, а не смысл; смысл оценивается вручную.

## Настройки и команды

`rag.inputDir`, `rag.outputDir`, `rag.chunkSizeChars` (1800), `rag.overlapChars` (200, строго меньше размера),
`rag.minChunkChars` (500, не больше размера), `rag.embeddingBaseUrl`, `rag.embeddingModel` (`bge-m3`),
`rag.embeddingTimeoutMs`; для поиска — `rag.chunkStrategy` (`structure`), `rag.retrievalMode` (`rewrite-filter`),
`rag.candidateTopK` (10), `rag.topK` (5, не больше `rag.candidateTopK`; оба от 1 до 20), `rag.similarityThreshold`
(0.55, от −1 до 1), `rag.questionsFile`; для чата — `rag.historyTurns` (6, от 1 до 20) и `rag.dialogFile`. Полный список — [docs/configuration.md](../../../../../docs/configuration.md).
Команды: `rag index`, `rag compare`, `rag calibrate`, `rag ask`, `rag on`, `rag off`, `rag eval`, `rag citations`, `rag dialog`,
`rag state`, `rag reset` —
[docs/commands.md](../../../../../docs/commands.md).

## Ограничения

- Размеры в кодовых точках, не в токенах; токены известны только суммой на стратегию (по пакетам из 8 текстов).
- Frontmatter и переводы строк нормализуются; только `.md`, без PDF и TXT.
- Блок длиннее лимита в `structure` делится окнами как в `fixed`; такие блоки видны в метрике разорванных блоков.
- Время — один локальный прогон после прогрева.
- Поиск — линейный перебор; порог 0.55 привязан к модели эмбеддингов `bge-m3` и корпусу FEOD, сетка калибровки — четыре значения.
- Индекс читается целиком на каждый `rag ask`; при другой модели эмбеддингов (digest) поиск отказывается работать.
- Метрики считаются по файлам итоговых чанков: это не оценка релевантности чанков и не качество ответа; уменьшение
  контекста не доказывает улучшение ответа. Rewrite может изменить смысл запроса.
- `rag eval` — один прогон, DeepSeek недетерминирован; разброс между прогонами не измерен. `rag calibrate` работает на
  одном наборе вопросов и одном корпусе. Токены и стоимость не считаются: `ModelPort` их не возвращает.
- Нормализация цитаты не распознаёт перефразирование; дословная цитата не доказывает, что ответ ей следует, — смысл
  оценивается вручную. Ссылки `[N]` внутри текста ответа и позиция цитаты в документе не проверяются.
- При пройденном пороге отказ зависит от модели; порог откалиброван для поиска, отдельного порога отказа нет. Нарушение
  формата не повторяется: замечание остаётся в `problems`.
- Специализированного реранкинга нет. Диалог живёт только в памяти: сессии REPL или процесса `rag serve`; окно истории обрезает старые ходы, память задачи
  их не заменяет и зависит от модели (может записать вопрос или утверждение ассистента). В `baseline` и `filter` follow-up ищется
  по исходной формулировке, без памяти и истории; rewrite с памятью может увести запрос от темы вопроса.
