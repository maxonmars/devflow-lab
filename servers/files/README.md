# files MCP server

Поиск, чтение и запись Markdown-файлов проекта для команды `files <цель...>` ([ADR 0005](../../docs/adr/0005-files-assistant.md)).
Host запускает сервер по stdio: `node src/app/main.ts --root <project.root>`. Первую фазу команды (поиск и чтение)
выполняет модель, запись — только host после подтверждения человека; `files_write` модели не показывается.

## Инструменты

| Инструмент | Вход | Что возвращает |
|---|---|---|
| `files_search` | `query` (1–200 символов), `path`, `ignoreCase` (по умолчанию `false`) | строки `путь:номер: текст` (поиск строки `git grep -F`, текст строки до 200 символов), не больше 100 совпадений |
| `files_read` | `path` (обязателен) | содержимое видимого текстового файла рабочей копии дословно, без заголовков, не длиннее 20 000 символов |
| `files_write` | `path` (только `.md`), `content` (до 100 000 символов) | `Записан файл <path>.` |

Текст `files_search`:

```text
Совпадения «<query>» (<всего>):
<путь>:<номер>: <текст>
Показано N из M.
```

Строка «Показано» есть только при обрезке; без совпадений — `Совпадений «<query>» нет.` Аннотации: у `files_search` и
`files_read` — `readOnlyHint: true`; у `files_write` — `readOnlyHint: false`, `destructiveHint: true`,
`idempotentHint: true`, `openWorldHint: false`. Пути — относительно корня проекта.

`files_read` отдаёт содержимое без обёртки: на этом строится проверка «файл не изменился» перед записью в host. Слишком
большой, двоичный и не-UTF-8 файл — ошибка, а не обрезанный текст.

## Песочница

- Видимые файлы — `git ls-files --cached --others --exclude-standard` внутри `--root`: отслеживаемые и неотслеживаемые,
  но не игнорируемые. `.env` и `.local/` не видны ни поиску, ни чтению, ни записи.
- Чтение и запись: путь должен совпасть ровно с одним видимым файлом, быть обычным файлом (не symlink и не каталог),
  а его `realpath` — лежать внутри `realpath(root)`.
- Запись: только `.md` (расширение в нижнем регистре, без сегмента `.git`; проверяет схема), только существующий файл,
  права файла сохраняются. Временный `<файл>.<uuid>.tmp` рядом и `rename`; при ошибке временный файл удаляется.
  Создавать, удалять и переименовывать файлы сервер не умеет.
- git запускается через `execFile` без shell, с `-C <root>`, `--literal-pathspecs`, `core.fsmonitor=false` и таймаутом
  5 с. Окружение git — `PATH`, `HOME`, `GIT_TERMINAL_PROMPT=0` и `LC_ALL=C`; ключи модели серверу не передаются.

## Ошибки

Ошибка возвращается результатом с `isError` и причиной: git не найден, корень не в репозитории, таймаут, слишком
большой вывод, файл не найден среди видимых (`FILE_NOT_FOUND`), не обычный файл (`NOT_A_FILE`), за корнем
(`OUTSIDE_ROOT`), двоичный (`BINARY`), слишком большой (`TOO_LARGE`), не удалось записать (`WRITE_FAILED`), иначе —
код завершения git. stderr git и абсолютные пути в текст не попадают.

## Ограничения

Видимость определяет git, поэтому корень проекта должен быть git-репозиторием. Поиск — только по строке, без
регулярных выражений. Игнорируемые файлы недоступны, даже если нужны.

## Проверка

`src/tests`: `readers.test.ts` — разбор `git grep` с подменённым git и тексты ошибок; `files.integration.test.ts` —
настоящий git во временном репозитории (видимость, символические ссылки, лимиты, запись и отказы);
`protocol.integration.test.ts` — `InMemoryTransport` и настоящий `Client`. Сборка проверяет список инструментов
собранного сервера.
