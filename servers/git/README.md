# git MCP server

Читающие инструменты git для ассистента проекта и AI-ревью. Host запускает сервер по stdio на каждую реплику `ask`,
`info <вопрос>` и на команду `review <база>` и передаёт корень проекта: `node src/app/main.ts --root <project.root>`.

## Инструменты

| Инструмент | Вход | Что возвращает |
|---|---|---|
| `git_branch` | — | текущая ветка и HEAD (короткий хеш, заголовок); отсоединённый HEAD; «коммитов пока нет» |
| `git_status` | — | `git status --short --branch` корня проекта, не больше 200 строк |
| `git_diff` | `staged` (по умолчанию `false`), `path`, `base` | `git diff --stat` и diff рабочей копии, индекса или ветки относительно `base` (`base...HEAD`), diff не длиннее 12 000 символов; `base` вместе со `staged: true` отклоняется |
| `list_files` | `path` | отслеживаемые файлы (`git ls-files`), не больше 300, с общим числом |
| `git_changed_files` | `base` | файлы, изменённые относительно merge-base (`base...HEAD`), со статусом `A M D R C T`, не больше 300 |
| `read_file` | `path` (обязателен) | содержимое отслеживаемого файла в HEAD, не длиннее 20 000 символов; двоичный файл не показывается |

Каждый результат — текст для модели и `structuredContent` по `outputSchema`. Аннотации всех инструментов:
`readOnlyHint: true`, `destructiveHint: false`, `idempotentHint: true`, `openWorldHint: false`.

`base` — ветка или коммит, например `origin/main`: от 1 до 200 символов `A-Z a-z 0-9 . _ / @ ^ ~ -`, без `..`, `:`,
пробелов и ведущего `-`. Перед чтением ref проверяется командой `git rev-parse --verify`.

### Текст `git_changed_files`

Его разбирает host в `review`, поэтому формат — контракт (`structuredContent` до host не доходит):

```text
Изменённые файлы относительно <base> (<total>):
<буква> <путь>
<буква> <новый путь> ← <старый путь>
Показано N из M.
```

Строка `← <старый путь>` есть только у R и C, строка «Показано» — только при обрезке. Без изменений — одна строка
`Изменённых файлов относительно <base> нет.` Пути — от корня проекта (`--relative`): их можно передавать как `path` в
`git_diff` и `read_file`.

## Песочница

- git запускается через `execFile` без shell, с `-C <root>` и таймаутом 5 с — короче таймаута MCP-вызова host.
- `--literal-pathspecs` выключает магию pathspec; `path` — относительный, без `..`, иначе схема отклоняет вызов.
- Pathspec по умолчанию — `.`: status, diff и список файлов не выходят за корень, даже если он подкаталог репозитория.
- `core.fsmonitor=false`, `--no-ext-diff` и `--no-textconv` не дают конфигу чужого репозитория запустить команду.
- `list_files` показывает только отслеживаемые файлы: игнорируемые (`.env`) и новые файлы не видны.
- `read_file` читает только HEAD (`git cat-file blob HEAD:./<path>`): игнорируемые, новые файлы и незакоммиченные
  изменения не видны.
- Окружение git — `PATH`, `HOME`, `GIT_TERMINAL_PROMPT=0` и `LC_ALL=C`; ключи модели серверу не передаются.

## Ошибки

Ошибка git возвращается результатом с `isError` и причиной: git не найден, корень не в репозитории, нет коммитов,
таймаут, слишком большой вывод, ref базы не найден (`UNKNOWN_REF`), файл не отслеживается в HEAD (`FILE_NOT_FOUND`),
иначе — код завершения. stderr git и пути вне корня в текст не попадают.

## Ограничения

Пути в diff — относительно корня репозитория, в status, списке файлов и `git_changed_files` — относительно корня
проекта. Неотслеживаемые файлы видны только в `git_status`. Длинный diff обрезается, сузить его можно параметром `path`.

## Проверка

`src/tests`: юнит-тесты разбора с подменённым git; `git.integration.test.ts` — настоящий git во временном
репозитории (ветки, detached HEAD, индекс, изменения относительно базы, `read_file`, подкаталог-корень, пустой
репозиторий, таймаут); `protocol.integration.test.ts` — `InMemoryTransport` и настоящий `Client`. Сборка проверяет
список инструментов собранного сервера.
