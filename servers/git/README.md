# git MCP server

Читающие инструменты git для ассистента проекта. Host запускает сервер по stdio на каждую реплику `ask` или
`info <вопрос>` и передаёт корень проекта: `node src/app/main.ts --root <project.root>`.

## Инструменты

| Инструмент | Вход | Что возвращает |
|---|---|---|
| `git_branch` | — | текущая ветка и HEAD (короткий хеш, заголовок); отсоединённый HEAD; «коммитов пока нет» |
| `git_status` | — | `git status --short --branch` корня проекта, не больше 200 строк |
| `git_diff` | `staged` (по умолчанию `false`), `path` | `git diff --stat` и diff рабочей копии или индекса, diff не длиннее 12 000 символов |
| `list_files` | `path` | отслеживаемые файлы (`git ls-files`), не больше 300, с общим числом |

Каждый результат — текст для модели и `structuredContent` по `outputSchema`. Аннотации всех инструментов:
`readOnlyHint: true`, `destructiveHint: false`, `idempotentHint: true`, `openWorldHint: false`.

## Песочница

- git запускается через `execFile` без shell, с `-C <root>` и таймаутом 5 с — короче таймаута MCP-вызова host.
- `--literal-pathspecs` выключает магию pathspec; `path` — относительный, без `..`, иначе схема отклоняет вызов.
- Pathspec по умолчанию — `.`: status, diff и список файлов не выходят за корень, даже если он подкаталог репозитория.
- `core.fsmonitor=false`, `--no-ext-diff` и `--no-textconv` не дают конфигу чужого репозитория запустить команду.
- `list_files` показывает только отслеживаемые файлы: игнорируемые (`.env`) и новые файлы не видны.
- Окружение git — `PATH`, `HOME`, `GIT_TERMINAL_PROMPT=0` и `LC_ALL=C`; ключи модели серверу не передаются.

## Ошибки

Ошибка git возвращается результатом с `isError` и причиной: git не найден, корень не в репозитории, нет коммитов,
таймаут, слишком большой вывод, иначе — код завершения. stderr git и пути вне корня в текст не попадают.

## Ограничения

Пути в diff — относительно корня репозитория, в status и списке файлов — относительно корня проекта. Неотслеживаемые
файлы видны только в `git_status`. Длинный diff обрезается, сузить его можно параметром `path`.

## Проверка

`src/tests`: юнит-тесты разбора с подменённым git; `git.integration.test.ts` — настоящий git во временном
репозитории (ветки, detached HEAD, индекс, подкаталог-корень, пустой репозиторий, таймаут); `protocol.integration.test.ts` —
`InMemoryTransport` и настоящий `Client`. Сборка проверяет список инструментов собранного сервера.
