# Демо: ассистент проекта `info <вопрос>`

Проверяет день 1 (ADR 0002): документация проекта в RAG, git MCP-сервер, `info` отвечает о проекте и его состоянии.
Нужны запущенная Ollama с `bge-m3` и `LAB_LLM_API_KEY` (DeepSeek).

## Шаги

```sh
npm run dev -- help
npm run dev -- rag index
npm run dev -- info "Какая сейчас ветка и что в ней изменено?"
npm run dev -- info "Где лежат MCP-серверы и какие правила для их инструментов?"
npm run dev -- info "Какие файлы лежат в docs/adr?"
npm run dev -- info "Какой рецепт борща?"
npm run dev
```

В REPL: `/info какая сейчас ветка?`, затем `/help` и `/exit`.

## Ожидаемый результат

- `help` печатает таблицы команд и настроек, среди команд — `info <вопрос...>`; ключ не нужен.
- Вопрос о ветке: в stdout строки `MCP: git › git_branch — выполнено` (обычно и `git_status`, `git_diff`), ответ
  называет текущую ветку и изменения, раздел «Данные проекта» перечисляет факты инструментов без замечаний; пустых
  «Источников», «Цитат» и «Фрагментов» в таком ответе нет.
- Вопрос об устройстве проекта: источники из README.md, AGENTS.md, ARCHITECTURE.md или README фич, цитаты с отметкой
  «найдена»; инструменты не вызываются.
- Вопрос о файлах: вызов `list_files`, в ответе только отслеживаемые файлы.
- Вопрос не о проекте: «Не знаю» с уточняющим вопросом; данных git ответ не выдумывает.

## Наблюдение 2026-10-13

Один прогон на машине разработки: Ollama 0.34.4, `bge-m3`, DeepSeek `deepseek-flash`, ветка `main` с незакоммиченной
документацией дня 1. Индекс: 17 документов, 64 чанка.

| Вопрос | Вызовы MCP | Источники | Время команды |
|---|---|---|---|
| Ветка и изменения | `git_branch`, `git_status` | нет, отбор пуст | 5,1 с |
| MCP-серверы и правила | нет | 5 фрагментов, 5 цитат найдены | не замерялось |
| Файлы в docs/adr | `list_files` | 1 фрагмент | не замерялось |
| Рецепт борща | нет | «Не знаю» моделью при пустом отборе | 2,8 с |

В ответе о ветке модель назвала `main`, HEAD и 10 изменённых файлов плюс новый ADR — совпало с `git status`. Время
включает запуск Node, git-сервера, rewrite, поиск и ответ модели; это один прогон, не распределение.
