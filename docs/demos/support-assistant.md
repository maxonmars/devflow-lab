# Демо: ассистент поддержки `support <тикет> <вопрос...>`

Проверяет день 3 (ADR 0004): тикет и клиент из JSON через MCP-сервер поддержки, документация продукта через RAG, один
вызов модели, ответ клиенту с разделами «Ответ», «Источники», «Данные тикета». Продукт — вымышленный «Acme Notes»
([examples/support-product](../../examples/support-product/README.md)). Нужны запущенная Ollama с `bge-m3` и
`LAB_LLM_API_KEY` (DeepSeek). Команды запускаются из корня репозитория: пути в `support.config.yaml` относительные.

## Команды

```sh
npm run dev -- --config-file examples/support-product/support.config.yaml rag index
npm run dev -- --config-file examples/support-product/support.config.yaml support T-1001 "Почему не работает авторизация?"
npm run dev -- --config-file examples/support-product/support.config.yaml support T-1002 "Почему не работает авторизация?"
npm run dev -- --config-file examples/support-product/support.config.yaml support T-1004 "Сколько стоит тариф с SSO?"
npm run dev -- --config-file examples/support-product/support.config.yaml support T-9999 "Не могу войти"
npm run dev -- --config-file examples/support-product/support.config.yaml support T-1001 "Какой рецепт борща?"
```

REPL: `npm run dev -- --config-file examples/support-product/support.config.yaml`, затем
`/support T-1003 что делать, если потерял телефон?`.

Ожидаемый результат:
- один и тот же вопрос по T-1001 (аккаунт `locked`, вход паролем) — блокировка на 30 минут и сброс пароля; по T-1002
  (`sso`, Business) — вход кнопкой «Войти через SSO»;
- каждый ответ — строка `MCP: support › get_ticket — выполнено`, блок «Ответ поддержки» с тремя разделами и
  «Контекстом ответа»;
- T-9999 — код 1 и «Ошибка · Тикет с таким идентификатором не найден.», модель не вызывается;
- вопрос не о продукте — модель говорит, что сведений нет, и просит уточнить; фрагменты по тексту тикета остаются в
  контексте.

## Наблюдение 2026-10-14

Машина разработки: Ollama с `bge-m3`, DeepSeek `deepseek-flash`, настройки модели по умолчанию. Время — вся команда
`npm run dev` от запуска до выхода, по одному прогону, не распределение.

**Измерения.**

| Сценарий | Код | Фрагментов в контексте | Источников в ответе | Время команды |
|---|---|---|---|---|
| `rag index` (4 документа, 6 чанков) | 0 | — | — | 2,1 с |
| T-1001 «Почему не работает авторизация?» | 0 | 5 | 3 | 3,1 с |
| T-1002 тот же вопрос | 0 | 3 | 2 | 3,0 с |
| T-1004 «Сколько стоит тариф с SSO?» | 0 | 5 | 3 | 3,0 с |
| T-9999 | 1 | — | — | 0,6 с |
| T-1001 «Какой рецепт борща?» | 0 | 5 | 2 | 3,5 с |
| REPL `/support T-1003 …` | 0 | 2 | 2 | 3,4 с |

Нарушений формата не было: строк «Ответ модели без разделов» и «Источники вне контекста» нет ни в одном ответе.

**Оценка.**
- T-1001 и T-1002 на один вопрос дали разные ответы по данным тикета: блокировка на 30 минут, ожидание или сброс пароля
  для T-1001; «Войти через SSO» и «пароль не сбрасывается» для T-1002. В T-1001 модель отдельно отметила, что причина
  не в SSO, потому что тариф Pro.
- T-1004: цен в документации нет, и модель сказала об этом, не выдумывая сумму; дальше — что SSO только на Business и
  как сменить тариф, со ссылками.
- T-1003: учтена переписка — поддержка уже запросила подтверждение личности. Факт из тикета модель при этом пометила
  ссылкой [2] на документацию: ссылки в тексте ответа не проверяются.
- Борщ: исходное ожидание плана — «ответ без источников» — не подтвердилось. Второй запрос к RAG — текст тикета —
  нашёл фрагменты о блокировке, и модель ответила о проблеме тикета, а про борщ сказала, что таких сведений нет, и
  попросила уточнить. Выдумки нет, но вопрос не по теме не даёт пустой отбор, пока в запросах есть тикет.
- Отбор широкий: корпус маленький, чанки крупные (несколько разделов `docs/auth.md` — один чанк), и порог 0.55
  пропускает почти весь корпус; в «Контексте ответа» видны и нерелевантные фрагменты (2FA в T-1001).
