# Демо: ассистент файлов `files <цель...>`

Проверяет день 4 (ADR 0005): модель сама ищет и читает файлы проекта, предлагает правки Markdown, host показывает diff и
записывает его только после «y» в терминале. Фикстура — [examples/files-demo](../../examples/files-demo/README.md):
README с таблицей лимитов, `src/limits.ts` и `change.patch`. Нужен `LAB_LLM_API_KEY` (DeepSeek); Ollama и индекс не нужны.
Команды запускаются из корня репозитория: `project.root` по умолчанию — репозиторий, файлы должны быть в git (видимость
определяет git, неотслеживаемые тоже видны).

## Сценарий 1. Найти все использования

```sh
npm run dev -- files "Найди все места, где используется withSessions, и кратко объясни роль каждого"
```

Ожидается: строки `MCP: files › files_search — выполнено`, возможно `MCP: files › files_read — выполнено`; ответ со списком
`путь:строка — роль` по нескольким файлам; правок и вопроса `[y/N]` нет, файлы не меняются.

## Сценарий 2. Обновить документацию по изменениям в коде

```sh
git apply examples/files-demo/change.patch
npm run dev -- files "Обнови examples/files-demo/README.md под незакоммиченные изменения кода в examples/files-demo"
git diff -- examples/files-demo
```

Ожидается: `MCP: git › git_diff` (или `git_status`), `MCP: files › files_read`, `Правка: examples/files-demo/README.md —
принята`, раздел «Предложенные изменения» с diff (`MAX_FILE_MB` 10 → 25 и новая строка `MAX_PARALLEL_UPLOADS`) и вопрос
`Применить изменения (файлов: 1)? [y/N]`. После «y» — `MCP: files › files_write — выполнено` и `Записано: …`; `git diff`
показывает правку README. Файлы кода модель не меняет: `propose_edit` принимает только `.md`.

Сброс перед повтором: `git checkout -- examples/files-demo`.

## Сценарий 3. Правка с подтверждением в REPL

```sh
git apply examples/files-demo/change.patch
npm run dev
```

В REPL: `/files Обнови examples/files-demo/README.md под незакоммиченные изменения кода в examples/files-demo`.
Ожидается то же, что в сценарии 2, включая вопрос `[y/N]`; после «y» — `Записано: …`, и REPL снова ждёт команду.
«y», набранный до появления вопроса, согласием не считается: строка уходит в REPL как реплика.

## Отказ и режимы без записи

Повторите сценарий 2 или 3 после сброса и `git apply`:
- на вопрос ответьте «n» или Enter — «Изменения не применены.», `git diff -- examples/files-demo/README.md` пуст;
- `npm run dev -- files "…" | cat` (stdin не терминал, `interactive: false`) — diff печатается, вопроса нет, сообщение
  «подтверждение возможно только в интерактивном терминале».

Если правка длинная и ответ обрывается с `INCOMPLETE_RESPONSE`, повторите с `--llm-max-output-tokens 2048`.
Если файл меняется между предложением и «y», он пропускается: «Пропущено: … — файл изменился после предложения правки».

## Наблюдение 2026-10-15

Машина разработки: DeepSeek `deepseek-flash`, настройки модели по умолчанию (`llm.maxOutputTokens` 1024, `INCOMPLETE_RESPONSE`
не возникал). По одному прогону каждого сценария, не распределение; время — вся команда от запуска до выхода. Фикстура
`examples/files-demo` на момент прогона не была закоммичена, поэтому `git_diff` вернул пустой результат, и модель
сравнивала код и README сама (`files_read`). Терминал имитировался псевдотерминалом (`script`). Ответ «y», поданный
сразу при запуске, запись не включил (результат — «Изменения не применены.», причина не выяснялась); ответ, поданный
через 30 с, после готового diff, сработал.

**Оценка.**
- Сценарий 1: ответ перечислил 8 мест с `путь:строка` (определение и рекурсивный вызов в `toolSources.ts:67,77`,
  `ask.ts:34`, `info.ts:17`, `review.ts:114`, `support.ts:39`, `files.ts:76,93`); сверка с `grep -rn withSessions apps/host/src`
  показала, что все места и номера строк совпали. Вхождения в тестах и документации модель отнесла к «не по делу».
- Сценарий 2: diff README — `MAX_FILE_MB` 10 → 25 и новая строка `MAX_PARALLEL_UPLOADS`; после «y» файл на диске
  отличается от исходного ровно этими двумя изменениями. Без TTY и при отклонённой записи файл не менялся.
- В прогоне без TTY принято две правки (на один файл), итоговый diff не проверялся на совпадение с ожидаемым.
- Число вызовов и формулировки меняются от прогона к прогону: в разных запусках модель читала разный набор файлов.
- Не проверено: REPL с реальной моделью (покрыт тестами app), пропуск файла, изменённого между предложением и «y»
  (покрыт тестами), прогон на закоммиченной фикстуре.
