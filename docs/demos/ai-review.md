# Демо: AI-ревью PR `review <база>`

Проверяет день 2 (ADR 0003): изменения ветки через git MCP-сервер, документация через RAG, один вызов модели, ревью с
разделами «Потенциальные баги», «Архитектурные проблемы», «Рекомендации» и комментарий в PR.
Нужны запущенная Ollama с `bge-m3` и `LAB_LLM_API_KEY` (DeepSeek).

## Локально

```sh
npm run dev -- rag index
npm run dev -- review no-such-ref
npm run dev -- review main
npm run dev -- --llm-timeout-ms 120000 --llm-max-output-tokens 4096 --review-output-file .local/review.md review main
```

Ожидаемый результат:
- неизвестный ref — код 1 и «Ошибка · Ref базы не найден в репозитории.», модель не вызывается;
- ветка без коммитов относительно базы — «Изменений относительно main нет.», модель не вызывается;
- ветка с коммитами — строки `MCP: git › git_changed_files — выполнено`, затем `git_diff` и `read_file` по файлам, блок
  «AI-ревью» с тремя разделами и «Контекстом ревью»; `.local/review.md` совпадает с текстом блока.

## В CI

Предусловие: секрет репозитория `LAB_LLM_API_KEY` в Settings → Secrets and variables → Actions.

1. Ветка `demo/ai-review` с намеренными проблемами — например, импорт `../rag/format.ts` (не `index.ts`) из
   `features/review` и off-by-one в лимите файлов `app/review.ts`. Открыть PR в `main`.
2. Workflow «AI review» публикует комментарий с маркером `<!-- ai-review -->`, Job Summary содержит тот же текст.
3. Push ещё одного коммита — тот же комментарий обновлён, новый не создан.
4. Записать время job и шагов (Start Ollama, `rag index`, Review) для первого прогона без кэша и второго с кэшем,
   размер кэша. Демо-PR после записи закрыть, не мержить.

## Наблюдение 2026-10-13: локальный прогон

Машина разработки: Ollama 0.34.4, `bge-m3`, DeepSeek `deepseek-flash`, `--llm-timeout-ms 120000`,
`--llm-max-output-tokens 4096`. Коммитов в рабочем репозитории не было, поэтому изменения дня 2 закоммичены во
временном клоне; команды запускались с `--project-root <клон>` и отдельным `--rag-output-dir`. Время — `time` одной
команды, по одному прогону, не распределение.

**Измерения.**

| Сценарий | База | Изменённых файлов | В контексте | Фрагментов | Время команды |
|---|---|---|---|---|---|
| `rag index` клона | — | — | — | 20 документов, 78 чанков | 6,2 с |
| `review no-such-ref` | — | — | — | — | 0,6 с, код 1 |
| `review main` без коммитов | `main` | 0 | — | — | 0,6 с |
| Изменения дня 2 | `origin/main` | 53 | 16 | 5 | 15,2 с |
| Демо-ветка с двумя нарушениями | ветка дня 2 | 2 | 2 | 5 | 4,8 с |

В прогоне с 53 файлами бюджет 80 000 символов исчерпали первые по алфавиту файлы — документация и `apps/host` с полным
содержимым; 37 файлов, включая `servers/git` и `features/review`, ушли в «Не вошло в контекст». Время CI не измерено:
прогон на PR ещё не выполнялся.

**Оценка.** На демо-ветке ревью нашло обе заложенные проблемы: off-by-one в «Потенциальных багах» со ссылкой на строку и
импорт `../rag/format.ts` в «Архитектурных проблемах» со ссылкой на фрагмент с правилом «Фичи не импортируют друг
друга». На большом наборе часть пунктов опиралась на пропущенные файлы и была неверной: модель сочла, что
`docs/commands.md` не перегенерирован, хотя файл просто не вошёл в контекст. Номера строк в содержимом файлов модель
оценивает сама: в тексте `read_file` их нет.

## Ограничения

- Стоимость прогона не измеряется: ModelPort не возвращает usage.
- Порог 0.55 калиброван на вопросах; для запросов из diff он не калибровался.
- Крупный PR ревьюится частично, порядок файлов — как у `git diff --name-status`.
