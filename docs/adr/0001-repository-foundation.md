# 0001 — Основа репозитория

Статус: принято по подтверждению создания rag-lab.
Дата: 2026-09-29.

## Контекст

Пятая неделя курса посвящена RAG. В mcp-lab цель проекта, course.md, ARCHITECTURE.md и AGENTS.md написаны про
MCP-серверы; для RAG пришлось бы переписывать их и держать в одном репозитории две разные темы. Прежние блоки курса
тоже начинались в новом репозитории: код не переносили, технологические практики сохраняли.

## Варианты

Фича в mcp-lab не требует каркаса, но смешивает темы и оставляет в цели проекта только MCP.
Новый репозиторий с нуля повторяет уже отлаженные tooling, реестры настроек и команд.
Новый репозиторий с копией нужного каркаса даёт чистую цель и не повторяет работу.

## Решение

- Новый репозиторий rag-lab, раскладка npm workspaces `apps/host`; каталога `servers/` не было (с ADR 0009 — `servers/llm-gateway`).
- Из mcp-lab перенесены tooling, конфигурации Biome, TypeScript и Vitest, pre-commit и CI, ядро (Agent, ModelPort,
  ToolSource, AgentError), адаптер DeepSeek, CLI-адаптер, реестры настроек и команд, `ask` без инструментов.
- Не перенесены MCP-фичи, серверы MCP, зависимости `@modelcontextprotocol/*`, worker планировщика и связанные тесты.
- Ядро осталось без изменений: ToolSource нейтрален и пригодится позже, `ask` сейчас отвечает без инструментов.
- Правила границ tooling остались общими; правила про `servers/` срабатывают с появлением каталога (ADR 0009).
- Первая содержательная фича — `features/rag` (ADR 0002).

## Последствия

Agent и DeepSeek в первом задании недели напрямую не участвуют: их использует только `ask`.
Изменения ядра проходят ADR, как и раньше. Изменение правил в mcp-lab сюда не переносится автоматически.

## Проверка

`npm run check` выполняет lint, typecheck, границы, структуру, документацию, тесты с coverage и сборку.
