# 0005 — Ассистент для работы с файлами: `files <цель...>`, MCP-сервер файлов, правки с подтверждением

Статус: принято по заданию дня 4.
Дата: 2026-10-15.

## Контекст

Задание дня 4 — ассистент, который работает с файлами проекта: ищет по нескольким файлам, читает рабочую копию и
git-изменения, предлагает правки. Два сценария: найти все использования API или компонента; обновить документацию по
изменениям в коде.

Git-сервер (ADR 0002) только читает, а `read_file` отдаёт HEAD, а не рабочую копию. Песочница (корневой AGENTS.md)
разрешает запись только по ADR и после подтверждения человека перед вызовом; сейчас такого механизма нет.

## Варианты

- Только diff без записи: безопасно, но человеку остаётся применять правки руками.
- Модель пишет сама, подтверждение запрашивается на каждый вызов записи: подтверждение посреди цикла инструментов
  требует нового контракта в Agent/ToolSource и показывает человеку фрагменты, а не итог.
- Предложение → diff → подтверждение → запись через host (выбрано): модель только предлагает правки, человек видит
  итоговый diff целиком, запись выполняет host отдельной сессией.

## Решение

- Команда `files <цель...>` (`app/files.ts`) в две фазы. Фаза plan: модель, git-сервер и files-сервер; `Agent` с
  промптом фичи и лимитом `FILES_MAX_TOOL_CALLS` (15) отвечает на цель, правки копятся в памяти. Фаза apply: после
  ответа «y» открывается новая сессия одного files-сервера, каждый файл перечитывается и пишется, только если не
  изменился с момента предложения. Модель на этапе подтверждения не работает.
- Модель видит инструменты git-сервера, кроме `read_file` (HEAD путал бы с рабочей копией), `files_search`,
  `files_read` и локальный `propose_edit { path, old, new }`. `files_write` от модели скрыт (`withoutTools`): его
  вызывает только host.
- `propose_edit` (`features/files`) принимает правку только для `.md`, если `old` встречается в текущем содержимом ровно
  один раз; несколько правок одного файла применяются последовательно. Ошибка возвращается модели результатом с
  `isError`, чтобы она могла исправиться.
- MCP-сервер `servers/files`: `files_search` (`git grep`), `files_read`, `files_write`. Видимые файлы — отслеживаемые и
  неотслеживаемые, но не игнорируемые (`git ls-files --cached --others --exclude-standard`): `.env` и `.local/` не
  видны. `files_write` заменяет только существующий видимый обычный `.md` (не symlink, `realpath` внутри корня),
  атомарно: временный файл рядом и `rename`. Ограничение `.md` проверяет сервер; `propose_edit` дублирует его ради
  ранней обратной связи модели.
- Diff считает host (`features/files`, библиотека `diff`) и печатает unified diff по каждому файлу.
- Подтверждение `[y/N]` доступно при TTY — одной командой и в REPL. Ответ читает тот же readline, что и строки REPL
  (`rl.question`): второго читателя stdin нет, ввод до вопроса уходит в REPL и согласием не считается. Согласие — «y», «yes»,
  «д», «да»; всё остальное и EOF — отказ. Иначе печатается diff и сообщение, что изменения не применены.
- Новых настроек нет: лимиты — именованные константы. Core не меняется.

## Последствия

- Без TTY (CI, `| cat`) изменения только показываются; флага `--yes` нет.
- Содержимое прочитанных файлов уходит провайдеру модели.
- Инструкции внутри файлов (prompt injection) ограничены тем, что запись без человека невозможна, а записываются
  только `.md`.
- Запись по файлам идёт по одному без транзакции: при ошибке одного остальные всё равно пишутся, итог печатается по
  каждому файлу.
- Ответ с правкой ограничен `llm.maxOutputTokens`; при обрыве (`INCOMPLETE_RESPONSE`) помогает
  `--llm-max-output-tokens`.
- Пути `git_diff` — от корня репозитория, у files-инструментов — от `project.root`; при `project.root` в подкаталоге
  модель может их спутать.
- Видимость определяет git, поэтому `project.root` должен быть git-репозиторием.
- Создание, удаление, переименование и запись не `.md` не поддерживаются.

## Проверка

`npm run check`. В него входят:
- тесты сервера: разбор `git grep`, видимость файлов, запись и отказы (не `.md`, игнорируемый, symlink), протокол;
- фича files: принятие и отклонение правок, diff;
- `files` в app с подменёнными сессиями: ответ `y`, `n`, без TTY, в REPL `y` и `n` после вопроса и `y` до него, изменение файла между фазами, скрытые инструменты;
- `files` с настоящим сервером из host на временном репозитории;
- smoke собранного сервера со списком инструментов.

Ручной прогон — [docs/demos/files-assistant.md](../demos/files-assistant.md).
