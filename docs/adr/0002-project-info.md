# 0002 — Ассистент проекта: `info <вопрос>`, git MCP-сервер, ответ с инструментами

Статус: принято по заданию дня 1.
Дата: 2026-10-13.

## Контекст

Задание дня 1 — ассистент разработчика:
- RAG по README, docs и описаниям API проекта;
- MCP с текущей git-веткой (по желанию — список файлов и diff);
- команда `/help`, которая отвечает на вопросы о проекте по документации и его контексту.

RAG по документации уже есть (ADR 0001): корпус — `rag.include` внутри `project.root`, в него входят и сгенерированные
справочники команд и настроек. `ask` умеет цикл MCP-инструментов, но серверов не было. `help` занят таблицами справки.

## Варианты

**Команда.**
- Необязательный аргумент `help [вопрос...]`: без вопроса — таблицы справки, с вопросом — ассистент. Проверка в REPL
  показала, что одна команда с двумя смыслами путает: справку по CLI и вопрос о проекте трудно различить.
- Переименовать таблицы справки в `commands` и отдать `help` ассистенту — ломает привычный `--help`.
- Отдельная команда `info <вопрос>`: `help` остаётся классической справкой, `/help` из задания соответствует `/info`.

**Связка RAG и MCP.**
- Host до вызова модели сам собирает ветку и статус и кладёт их в сообщение: один вызов модели, но diff и список
  файлов модель запросить не может.
- Модель получает фрагменты и инструменты и сама выбирает вызовы (tool use): отвечает и о документации, и о
  состоянии репозитория, ценой дополнительных вызовов.

## Решение

- Отдельная команда `info <вопрос...>` (в REPL — `/info вопрос`); без вопроса — ошибка «Не указан вопрос о проекте».
  `help`, `--help` и `-h` — прежняя справка без аргументов, ключ не нужен. Если ответ опирается только на данные
  инструментов, CLI не печатает пустые «Источники», «Цитаты» и «Фрагменты».
- Новый workspace `servers/git` — MCP-сервер с четырьмя читающими инструментами: `git_branch`, `git_status`,
  `git_diff`, `list_files`. Host запускает его тем же Node с `--root <project.root>` на каждую реплику `ask` и
  `info <вопрос>`.
- Песочница сервера:
  - `execFile` без shell, таймаут 5 с;
  - `--literal-pathspecs`, путь только относительный и без `..`;
  - pathspec по умолчанию `.` — вывод не выходит за корень проекта;
  - `core.fsmonitor=false`, `--no-ext-diff`, `--no-textconv` — конфиг репозитория не запускает команды;
  - `list_files` показывает только отслеживаемые файлы, поэтому `.env` не виден;
  - серверу не передаются ключи модели.
- Фича rag получает необязательные `tools` (`ProjectTools`: источник и лимит вызовов):
  - инструкция берётся из `prompts/project.md`;
  - модель вызывается и при пустом отборе, потому что ответ может дать инструмент;
  - ответ может содержать раздел `## Данные проекта` со строками `- инструмент: факт`.

  Разбор сверяет факты с реально вызванными инструментами (замечание `tool-not-called`). Ответ только по данным
  инструментов не требует источников и цитат. Без `tools` поведение `rag ask` не меняется.
- `app/info.ts` до запуска сервера проверяет параметры поиска, создаёт модель и открывает индекс. Затем открывает
  MCP-сессии и вызывает `answerWithRag` с инструментами; лимит вызовов `INFO_MAX_TOOL_CALLS = 4`.

## Последствия

- Каждая реплика `ask` и `info <вопрос>` запускает процесс git-сервера, примерно десятки миллисекунд на старт.
  Постоянной сессии нет.
- Rewrite и поиск выполняются и для вопросов о состоянии репозитория: при пустом отборе в сообщение уходит «Подходящих
  фрагментов нет», а ответ даёт инструмент.
- Факт из «Данных проекта» проверяется только по имени вызванного инструмента. Текст факта с результатом инструмента
  не сверяется, его смысл оценивается вручную.
- Пути в diff — от корня репозитория, в status и списке файлов — от корня проекта.
- Вопросы о коде, а не о документации, ассистент покрывает только списком файлов и diff: содержимое исходников в
  корпус не входит.

## Проверка

`npm run check`. В него входят:
- тесты сервера на настоящем git во временном репозитории и через протокольный `InMemoryTransport`;
- запуск настоящего сервера из `ask`;
- `info` с подменённой сессией и моделью;
- smoke собранного сервера из другого каталога.

Ручной прогон — [docs/demos/project-info.md](../demos/project-info.md).
