# Направления недели

Седьмая неделя курса — «Add AI to work pipeline»: встроить агента в рабочий процесс разработчика. Конкретные
задания выдаются по одному; строки ниже — ориентир по вводному видео, а не разрешение реализовывать будущие задания
заранее.

| День | Тема | Опора в каркасе |
|---|---|---|
| 1 (31) | Ассистент разработчика: RAG по README, docs и схемам проекта; MCP — минимум текущая git-ветка, по желанию список файлов и diff; `/help <вопрос>` отвечает о проекте по документации и контексту | `rag index`/`rag ask`, `ask` с MCP-сессиями, `project.root` |
| 2 (32) | Автоматизация ревью кода: PR создан → diff → RAG по документации → LLM-ревью → комментарий в PR (`.github/workflows/ai-review.yml`, `pull_request` opened/synchronize) | RAG, ModelPort, CI-workflow |
| 3+ | Вероятно: пайплайны (триггеры PR/schedule/event, цепочки, мониторинг); субагенты (fan-out, chain, router; spawn → execute → report → merge); обработка ошибок (retry до 3 попыток, fallback на другую модель или упрощённый промпт, human-in-the-loop); метрики и тестирование пайплайна | — |

Реализовано: каркас недели (ADR 0001) — RAG по документации проекта и `ask` с циклом MCP-инструментов без серверов.

## Ориентиры из видео

- RAG — память агента (документация и код), MCP — руки (взаимодействие с внешним миром), Pipeline — автоматизация,
  Subagents — делегирование сложных задач.
- AI-пайплайн: TRIGGER (PR, расписание, событие) → INPUT (diff, docs, data) → AGENT (RAG + LLM + Tools) →
  OUTPUT (review, file, message).
- Инструмент: имя и описание для модели, параметры для валидации, `execute` для логики; исполнитель ищет инструмент
  в реестре и возвращает ошибку «unknown tool». В каркасе это `ToolDefinition`, `ToolSource`, `combineToolSources` и
  `AgentError UNKNOWN_TOOL_CALL`.
- Песочница: опасные операции (удаление файлов, git push, изменение конфигов, сетевые запросы, произвольные скрипты)
  требуют подтверждения; безопасные (чтение файлов, git status/diff/log, поиск по коду, компиляция и тесты, анализ
  структуры) выполняются автоматически.
- Метрики пайплайна: latency P50/P95/P99 (цель для ревью < 60 с), стоимость прогона (< $0.10 за PR), качество
  (golden set и ручная оценка, > 80 % полезных), надёжность (> 95 % прогонов без ошибок и fallback).
- Тестирование: golden set из 10–20 PR с известными багами, A/B промптов и моделей, smoke-тест перед деплоем,
  ручная оценка с обратной связью в промпт.

## Открытые вопросы

**Ollama в GitHub Actions (день 2).** RAG каркаса использует локальную Ollama, в раннере её нет. Варианты:

- Ollama и `bge-m3` (около 1,2 ГБ) в раннере с кэшем `~/.ollama` — время запуска против цели < 60 с;
- self-hosted раннер с Ollama;
- облачные эмбеддинги — новый адаптер EmbeddingPort и секрет; у DeepSeek API эмбеддингов нет;
- лексический поиск без эмбеддингов за отдельным портом;
- без RAG в CI: AGENTS.md и ARCHITECTURE.md целиком в контексте ревью;
- ревью локально и публикация комментария через `gh`.

Ограничения GitHub: секреты недоступны `pull_request` из форков; публикации комментария нужно
`permissions: pull-requests: write`.

**`/help` и справка.** `help` уже печатает таблицы команд и настроек; решение — в ADR 0002 (ориентир в ADR 0001).
